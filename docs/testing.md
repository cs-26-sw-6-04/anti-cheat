# Testing Strategy

BPF LSM programs must be loaded, attached, and triggered against the real kernel path; `BPF_PROG_RUN` cannot stand in for that. The suite is an integration suite: every test runs a real attacker process against a real target process, with and without the enforcers active.

## Scenario shape

Each test is a declarative spec passed to `run_scenario`, which always executes two sections:

1. **attack succeeds (no enforcer)** — no session. The attack must succeed *and* `verify_success` must confirm the side-effect actually happened (bytes exfiltrated, memory mutated). Exit code alone is not enough: a silently-failed syscall would otherwise look like a pass.
2. **protected** — a session is opened first and the attack must fail with the correct enforcer attributing it.

The two halves answer different questions: section 1 proves the test exercises a real attack vector on this kernel, section 2 proves the enforcer denies it. Without section 1, a no-op test (e.g. `return 1` unconditionally) would pass the "protected" check.

Random tokens (initial flag, mutation payload) per run, generated by `ac::random_token()`, so an attacker cannot hardcode them.

## Why no per-syscall enforcer attribution

`process_vm_{readv,writev}` and `ptrace(PTRACE_ATTACH)` all hit `lsm/ptrace_access_check` with `PTRACE_MODE_ATTACH_REALCREDS`. The kernel does not distinguish them at that hook, so splitting one enforcer into `AC_ENF_PTRACE` + `AC_ENF_PROCVM` would be a lie at the granularity the kernel actually offers. `AC_ENF_MEMORY` owns the whole attach-mode domain and fires for all three.

Likewise, there is no runtime on/off bit per enforcer. Each enforcer's domain check (loader pid vs. subtree ancestry) is what decides whether it fires; the two domains are disjoint, so a runtime toggle would have nothing to arbitrate. Debug and Release run the identical code path.

## Running

```sh
mise x -- conan install . -s build_type=Debug --build=missing
cmake --preset conan-debug
cmake --build --preset conan-debug --parallel
ctest --preset conan-debug                              # baseline only
sudo ctest --preset conan-debug --output-on-failure     # with live BPF
```

Without root, the "protected" section skips cleanly via Catch2 `SKIP`. The "attack succeeds" section still runs and must pass — that pre-flight check proves the attack actually works on this kernel before we claim the enforcer blocked it.
